## Critical Learnings

### Six runs of P5-T4, and what each cost

Four of six never measured anything. Twice blocked because auto mode was on in a session started
believing it was off; once because the launch dropped `--plugin-dir` and the session diagnosed it
as a plugin defect; once because the fixture had one file, which pins the breaker's
introduced-rate at 100% and makes the loop's own gate unsatisfiable. **Every one of those was a
precondition nobody checked.** Run 5's brief added the plugin check and run 6 passed first time.

### `/verify` cannot be invoked by the model

`Skill('verify')` refuses with `disable-model-invocation`, and the refusal ends *"Do not replicate
this skill's workflow by other means."* `adversarial-loop` Phase 1 step 4 said "Invoke `/verify`"
— unexecutable since it shipped — and `code-review-integration.md` asserted all three built-ins
were model-invocable. Measured: `code-review` loads, `security-review` loads, `verify` refuses.
**Design decision Q5 rests on that delegation.** The step now asks the user; run 6 exercised it
end to end and `/verify` earned its place, surfacing four things no static lens produced.

### The thing that would have caught most of this, and is cheap

A one-command headless probe:
`claude -p --plugin-dir <p> --allowedTools=Skill,Read,Bash "<instruction>"`. It settled the
`--plugin-dir` question in minutes and exercised the read-boundary hard-stop rule for the first
time ever. It was available from Phase 1 and nobody reached for it, because "behavioural test"
was imagined as a session a human sits through.

### Problems Solved

**The waiver scheme was anchored on line numbers**

- **Symptom**: any edit to `check-guards` would silently unhook every waiver below it, and the
  ratchet could not see it — moving a mutant from `waived` to `survivors` leaves the kill count
  unchanged.
- **Solution**: mutants now carry a key — `<scope> | <enclosing block> | <statement> | <operator>`
  — with `#n` only where two identical statements share a block. Falsified by shifting every line
  in `check-guards` down by two: all 48 waivers still bound.
- **Location**: `plugin/scripts/lib_mutate.py`, `plugin/scripts/test-guards`

**A ratchet on one number cannot see the invariant it protects**

- **Symptom**: shape 4 added ~60 lines and the sweep went 0 → 16 survivors, while `killed` rose
  244 → 299 because the total rose too. The gate stayed green while every-mutant-killed-or-argued
  quietly stopped being true.
- **Solution**: closed back to 0 surviving. **Not** fixed: the ratchet still watches kills.
  Changing what it watches is a decision.

## Watch Out For

- ⚠️ **Fenced `bash` blocks run under zsh.** `PIPESTATUS` is undefined, unquoted expansions are
  not word-split. Two shipped defects came from exactly that, and both survived four review
  rounds of *reading* the file. See `.claude/wb/knowledge.md`.
- ⚠️ **`grep` is ugrep despite `grep --version` claiming BSD grep.** Flag support varies with
  invocation; do not write a rule about which flags work, write the status guard.
- ⚠️ **`docs/plans/` is gitignored.** Every write there needs `git add -f`, every time, including
  already-tracked files. This is R6-T2 and it silently swallowed both round plans.
- ⚠️ **The bare skill name resolves to a personal copy.** `Skill('adversarial-loop')` gets 236
  lines from `~/.claude/skills`; `Skill('wb:adversarial-loop')` gets the shipped 379. The prefix
  decides, deterministically. That is what P5-T5 removes.
- ⚠️ **Verify the plugin loaded before drawing any conclusion from a session's behaviour**:
  `claude --plugin-dir <p> plugin details wb` must print `3.0.0` and `Source: wb@inline`.
