# Handoff — the 94 surviving generated mutants

## The task

`plugin/scripts/test-guards --generated` mutates `check-guards` mechanically and reports
**198 of 293 killed (67%)**. The 94 survivors are listed, grouped by source line with the code
at that line, in:

```text
plugin/scripts/fixtures/mutation-survivors.txt
```

**For each survivor: kill it with a corpus case, or waive it with an argument.** Nothing else
is asked. The file is regenerated on every sweep, so it stays current as you work.

## Why this exists, in one paragraph

An earlier suite reported `12/12 mutations caught`. Those twelve were written by the same
session that wrote the tool *and* the corpus, so each had a matching case almost by
construction. An independent reviewer, given the implementation and not the corpus, wrote 24
mutations and **20 survived**. The generated sweep exists so that number cannot be flattered
again: a generator has no blind spot correlated with the author's, because it is not reasoning
about the problem — it walks the syntax tree and changes one thing.

## Start here

Do **not** work top-to-bottom. The 94 are 57 source lines; the shape of them:

| Operator | Count | What it usually means |
| -------- | ----- | --------------------- |
| `int` | 41 | a constant `±1`. Often equivalent — many are slice bounds or counters no input distinguishes |
| `del` | 31 | a deleted statement. **9 delete a docstring or comment line and are near-certainly equivalent** |
| `regex` | 14 | **the highest-value group.** This tool's decisions live in its patterns |
| `cmp` | 5 | a comparison flipped |
| `bool` | 3 | `and` ↔ `or` |

The four groups I would open first, with my reading — **check it rather than trusting it**:

- **`L96` (6 mutants)** — `elif ch == '#' and (i == 0 or line[i - 1].isspace()):`, the
  quote-aware comment stripper. Six survivors on one decision line is the strongest signal in
  the file. A case needs a `#` mid-token that is *not* a comment, outside quotes.
- **`L228`/`L229` (7)** — the glob window counter and its `>= GLOB_WINDOW` test. The
  trailing flush at end-of-input probably rescues both, which would mean the window size is
  untested at any value. Worth confirming before writing cases.
- **`L177` (3)** — `_is_guard`'s regex. Weakenings survive, so the guard-recognition rule
  is under-covered.
- **`L133`/`L134`/`L143`/`L147` (12)** — `substitutions()`'s span arithmetic. Likely
  a mix: some genuinely equivalent, some real.

## The rules that keep this honest

1. **A corpus case is derived from the fixture content, never from the tool's output.**
   Deriving expectations from what `check-guards` currently prints encodes its bugs as its
   specification. Cases assert `(line, shape)`, not just the exit code — asserting the exit
   code alone let mutations that reported every finding at line 1 pass.
2. **A waiver carries an argument, not an entry.** `fixtures/mutation-waivers.json`. The one
   existing waiver is the model: *why no case can distinguish the two behaviours*. "It's
   probably fine" is not a waiver.
3. **The ratchet may not fall.** `fixtures/mutation-ratchet.json` holds `{"killed":198}`.
   The sweep exits 1 if the count drops, so removing an inconvenient mutant is not a way to
   make it green.
4. **Run the criterion before the fix.** If a new corpus case passes before you change
   anything, it is not testing what you think.
5. **The survivor list is not a bug list.** Many entries are constants no realistic input
   distinguishes. Raising the kill rate by writing contrived cases would be fitting the corpus
   to the tool — the exact failure this apparatus exists to prevent.

## Commands

```bash
./plugin/scripts/test-guards              # fast: corpus 54/54, integrity 9/9, mutations 22/22 (~20s)
./plugin/scripts/test-guards --generated  # the sweep, ~80s; rewrites the survivor list
./plugin/scripts/check                    # every gate; does NOT run the sweep, deliberately
```

`check` requires `shellcheck`, `markdownlint-cli` and `python3`, and fails loudly naming
the install command if one is missing.
